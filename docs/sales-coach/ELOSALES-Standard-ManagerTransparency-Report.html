03Framework spine, audit & what’s yours to decide

Built to the spec, governed by the framework — and honest about what isn’t finished.

Framework the build satisfies

  • A18 — surfacing rep data to a manager, the label is the defense: Strengths / Growth areas, grades as targets, no F, no leaderboard.
  • A10 — no shadow read: the manager sees the identical numbers the rep sees; same endpoint, same computation.
  • A11 — mirror not verdict: each letter grade travels with its /10; strengths/growth are derived from those counts.
  • §3.5 / §3.6 — no fabricated measure; a thin sample shows “still accumulating”.
  • §3.4 — a failed read shows an error, not zeros (fixed in audit).
  • AMD-006 — built foundation-up: data → APIs → composition → surface; Expert isolation proven by diff.

Honest status

  • BUILT + gate-verified: tsc, lint, production build, 849 tests green.
  • NOT TESTED live: no route has run against a real DB/auth here.
  • 0187 UNAPPLIED: apply it, then the purge cron needs CRON_SECRET + a vercel entry (after 0187).
  • Purge cron dormant until wired — same sequencing discipline as the other crons.
  • Grade bands (the /10→letter cutoffs) are a one-line tunable constant, flagged for you.

Audit result (against the framework, actual files re-read)

  • Fixed — §3.4: manager views rendered fetch failures as empty/wrong content → now an honest error state.
